# 🎯 C++ Fundamentals & DSA Preparation Project — Objectives

This document is intended to be used **as a prompt/context input** inside Cursor IDE (or any AI-assisted coding environment).

Its purpose is to guide:

* 📐 **Project planning**
* 🔍 **Code review & self-review**
* 📚 **Structured learning & concept reinforcement**

---

## 1. High-Level Objective

Build a **strong, interview-ready foundation in C++ and Data Structures & Algorithms (DSA)** by:

* Mastering C++ fundamentals deeply (not memorizing syntax)
* Applying those fundamentals to implement DSA correctly and efficiently
* Writing **clean, safe, and explainable code**

The goal is **not just solving problems**, but understanding *why* solutions work and *how* to improve them.

---

## 2. Core Principles (Must Be Followed)

When planning, writing, or reviewing code, always optimize for:

1. **Correctness first**
   The program must work for all valid and edge cases.

2. **Clarity over cleverness**
   Readable code is preferred over smart-looking code.

3. **Reasoned decisions**
   Every choice (data type, algorithm, condition) should have a reason.

4. **Progressive improvement**
   Start simple → then optimize → then clean up.

5. **Explainability**
   I should be able to explain the solution line-by-line in plain language.

---

## 3. C++ Fundamentals — Objective Scope

This project treats C++ as a **tool for thinking**, not just a language.

### 3.1 Topics to Master

* Data types (primitive, derived, user-defined)
* Signed vs unsigned behavior
* Functions & default arguments
* References and pointers
* Memory basics (stack vs heap)
* Control flow (if, loops, switch)
* Random number generation (`<random>`)
* Error handling (exceptions, `std::invalid_argument`, etc.)
* Input validation
* Const correctness
* Basic STL usage (`vector`, `string`, `map`, etc.)

### 3.2 Fundamental Learning Objective

> Understand **what the compiler does**, **what memory is used**, and **what can go wrong**.

Every piece of code should answer:

* What does this line do?
* Why is this type chosen?
* What happens in edge cases?

---

## 4. DSA Preparation — Objective Scope

DSA is treated as **applied problem-solving**, not theory.

### 4.1 Data Structures to Implement & Understand

* Arrays
* Strings
* Linked Lists (SLL, DLL)
* Stack & Queue
* Hashing
* Trees (Binary Tree, BST)
* Heaps
* Graphs

### 4.2 Algorithms to Master

* Linear & Binary Search
* Sorting algorithms (basic → efficient)
* Recursion & backtracking
* Sliding window
* Two pointers
* Greedy algorithms
* Basic dynamic programming

### 4.3 DSA Learning Objective

> Solve problems **efficiently**, not just correctly.

For every solution, evaluate:

* Time complexity
* Space complexity
* Possible optimizations
* Trade-offs

---

## 5. How This Prompt Should Be Used in Cursor IDE

### 5.1 For Project Planning

Use this document to:

* Break the project into phases (fundamentals → DSA)
* Define weekly or topic-based milestones
* Ensure prerequisites are learned before advanced topics

Questions to ask:

* Does this topic depend on another concept?
* Am I building depth or just moving fast?

---

### 5.2 For Code Review (Very Important)

When reviewing code, enforce the following checklist:

* Is the correct data type used?
* Are edge cases handled?
* Are magic numbers avoided?
* Is error handling present where needed?
* Is the algorithm optimal for constraints?
* Can this code be explained without hand-waving?

If code works but violates clarity or safety, it should be refactored.

---

### 5.3 For Learning & Improvement

Use this context to:

* Ask *why* a solution is better or worse
* Compare two approaches
* Identify hidden bugs or undefined behavior
* Improve readability and structure

Focus on:

* Understanding failures
* Learning from incorrect solutions
* Refining intuition over time

---

## 6. Definition of Success (DoD)

This project is successful if:

* I can implement core DSA from scratch in C++
* I understand memory and performance implications
* I can debug my own code confidently
* I can explain solutions clearly in interviews
* I can improve a working solution into a better one

---

## 7. Long-Term Outcome

This project should prepare me for:

* Technical interviews
* Competitive programming (optional)
* Backend / systems-level programming
* Learning advanced topics with confidence

The end goal is **thinking like an engineer**, not just writing code.

---

## 8. Instruction for AI / Cursor

When helping with this project:

* Prioritize correctness and reasoning
* Point out conceptual mistakes, not just syntax
* Explain *why* a change is better
* Highlight edge cases and pitfalls
* Avoid shortcuts that reduce understanding

Treat this project as a **learning-first, foundation-building effort**.
